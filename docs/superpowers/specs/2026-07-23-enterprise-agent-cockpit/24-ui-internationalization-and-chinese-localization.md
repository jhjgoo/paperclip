# 全站国际化与中文化规格

状态：已确认，待拆分实现计划与开发任务  
日期：2026-07-29  
归属：横切产品规格，覆盖既有 Paperclip 页面与后续企业驾驶舱页面

## 1. 背景与目标

当前 Paperclip 的用户界面以英文为主。企业驾驶舱首期面向中文业务团队，静态英文界面会提高理解和配置成本；同时，后续功能若不从一开始纳入国际化约束，中文化会不断遗漏。

本规格的目标是：一次性将既有 Paperclip 的所有用户可见静态界面文案纳入国际化体系，提供中文（简体）与英文切换，并把相同约束作为后续页面的交付门槛。

## 2. 已确认的产品决策

### 2.1 语言与默认值

- 支持 `zh-CN` 与 `en` 两种界面语言。
- 默认语言为 `zh-CN`；用户可主动切换为英文。
- 默认值只用于没有本地已保存偏好时；不存在依据浏览器语言自动推断或自动切换的行为。
- 语言切换后保持当前路由、筛选、展开状态和未提交表单状态。仅刷新由界面静态文案、日期、时间、数字和金额格式组成的呈现层。

### 2.2 偏好归属与入口

- 语言是个人偏好，不属于部门空间（现有 `Company`）、Project 或企业管理员设置。
- 首期只保存到浏览器本地存储，不新建服务端用户档案字段、API、数据库迁移或跨设备同步。
- 入口固定为「账户菜单 → 个人设置 → 显示与语言」。它不放入部门设置或 Instance Settings。
- 本地偏好无效、已移除或不可识别时，回退到 `zh-CN`。

### 2.3 文案边界

必须翻译：

- 导航、面包屑、按钮、表单标签与说明、弹窗、空状态、Toast、前端错误、状态/枚举展示文本、帮助文案；
- `aria-label`、`title`、占位符、确认提示等无障碍与辅助文案；
- 所有既有 Paperclip 路由、主要弹窗和可复用共享组件。

保持原样：

- 用户输入、Agent 输出、外部系统字段和事件、文件内容、代码、命令、URL、日志与原始运行 Transcript；
- 用户或外部系统自行提供的标题、描述、评论、Artifact、Work Product 和 Connector 数据。

日期、时间、数字和金额不写死英文格式，使用当前语言的 `Intl` 格式化。机器状态码、API 字段名和稳定标识不作为 UI 翻译对象；它们在必要处与已翻译的解释并列显示。

## 3. 统一术语

| 英文概念 | 中文界面术语 |
| --- | --- |
| Company | 部门空间 |
| Project | 项目 |
| Issue / Task | 任务 |
| Agent | 智能体 |
| Workspace | 工作区 |
| Environment | 运行环境 |
| Artifact | 工件 |
| SOP Run | SOP 运行 |
| Stage | 阶段 |
| Human Gate | 人工关卡 |
| Invocation | 调用 |

术语表适用于静态 UI，不能改写底层 API、数据库字段、日志或用户提供内容。已有领域规格中的权威概念不因 UI 翻译改变。

## 4. 技术边界

### 4.1 复用现有能力

实现复用现有 `i18next` 与 `react-i18next`，并保留单一 `translation` namespace。现有 `ui/src/i18n/` 目录、语言包自动加载和 locale 校验是唯一国际化基础，不增加国际化依赖，不引入第二套翻译服务。

实现调整包括：

- 将当前默认语言从 `en` 改为 `zh-CN`，并提供完整的 `zh-CN.json` 与 `en.json`；
- 在 i18n 初始化前读取本地语言偏好；切换时更新 i18n 运行时语言和该本地偏好；
- 在既有个人设置页增加「显示与语言」分区，不改变服务端 Profile API；
- 保留现有语言包结构校验，并扩展为以任一基准语言校验全部注册语言的 Key 树、插值变量和安全限制完全一致。

语言 Key 必须表达语义和页面归属，例如 `navigation.projects`、`sop.runCockpit.title`、`profile.displayLanguage.zhCn`。禁止以英文原文、页面序号或临时缩写作为 Key。

### 4.2 静态文案门禁

新增或修改的用户可见 React 文案必须通过翻译 Key 提供。门禁覆盖 JSX 文本、属性文案、Toast、错误映射和状态展示；技术常量可以存在，但需使用显式且范围最小的白名单。门禁不得扫描或要求翻译：测试 fixture、用户/外部数据、日志、代码样例、协议字段名和稳定机器标识。

这是一项交付门槛，不要求本规格阶段预先建立通用文案管理后台、翻译工作流或第三方翻译平台。

## 5. 页面迁移范围

本次为一个发布目标，实施时按风险和复用度分组，不能只发布局部中文页面：

1. 应用壳与共享组件：登录/引导、侧边栏、顶部栏、账户菜单、主题与个人设置、通用表单、状态、错误、弹窗、Toast、空状态和无障碍标签。
2. 核心业务页：Dashboard、部门空间、组织与智能体、项目、任务、任务详情/Timeline、目标、审批、成本、活动与搜索。
3. 复杂交互页：Project Workspace、运行与 Transcript、Artifact/Work Product、环境、工作区运行服务、Routines、导入导出和各类配置向导。
4. 企业管理与扩展页：Instance Settings、成员与权限、插件、Adapter、Skill、连接器及其他已注册 Paperclip 页面。
5. 已落地或后续落地的企业驾驶舱页面：SOP Studio、SOP Run Cockpit、Stage Detail、Human Gate、Resources、企业控制台和能力管理页面，从第一个页面起使用本规格的 Key、术语与验收标准。

路由、数据模型和业务行为不因这次国际化而改变。现有 M1 的 SOP Cockpit/Stage Detail 仍只具有已交付的最小只读能力；国际化不会把未实现的配置器、Gate 操作或 Agent 透明执行链伪装为已交付能力。

## 6. 验收与测试

### 6.1 自动验证

- 每一个注册语言包都与基准语言具备相同完整 Key 树；缺 Key、多余 Key、插值变量不一致或不安全内容均使测试失败。
- 静态用户可见硬编码文案门禁在 CI 中执行；允许项必须可审计且仅限技术常量。
- 语言偏好读写、无效值回退、刷新后恢复、运行时切换和 `Intl` 格式化均有针对性测试。

### 6.2 体验验收

- 在 `zh-CN` 模式遍历全部已注册路由及主要弹窗，平台静态 UI 不残留英文；外部原文和用户内容不计入残留。
- 在 `en` 模式执行相同遍历，不显示缺失 Key、中文回退或未翻译的静态中文。
- 在任一页面切换语言，当前路由与正在查看的数据保持不变；未提交的本地界面状态不得因切换丢失。
- 账户菜单能够进入个人设置的「显示与语言」区，选择任一支持语言后立即生效，并在同一浏览器下刷新后保留。
- 无障碍名称、悬浮提示、错误提示和空状态与主文案一起完成双语覆盖。

## 7. 明确非目标

- 服务端、数据库或用户档案的语言偏好同步；
- 自动探测浏览器语言；
- 第三种语言、机器翻译、翻译管理平台、翻译审批工作流；
- 翻译用户、Agent、外部系统或文件中的原始内容；
- 借国际化重构路由、权限、SOP Runtime、Task/Issue 事实模型或既有业务流程。

## 8. 与现有规格的关系

本文件是页面信息架构和交互的横切约束：它只规定如何呈现静态语言，不拥有 SOP、Agent、Connector、权限、Run 或 Artifact 的领域写模型。产品概念及业务边界继续以决策台账和子需求 01 至 10 为准；产生冲突时，领域规格优先，本文件只处理可见文案、语言偏好与格式化行为。
